I built SKY, a voice AI that runs a whole computer.

SKY is a bilingual desktop agent I designed and built from scratch. You say “Hey Sky” in English, Urdu or Roman Urdu, and it listens, understands, plans and acts: it plays music, sends WhatsApp messages and files, reads email, controls Windows and reads the screen. It runs on a single consumer GPU and keeps working offline.

The project

Why I built it

Most voice assistants stop at answering questions. I wanted one that could actually do the work on my own laptop, in the way I really speak: switching between English and Urdu in the same sentence, like “Haris ko call lagao” or “YouTube pe song chalao”.

That goal turned into a complete system. SKY has a real-time speech pipeline, a language model that turns speech into a structured JSON action plan, a tool layer that executes that plan on Windows, a computer-vision module that can find and click things on screen, a FastAPI backend with authentication, and a React web interface that shows each stage live.

The hardest problems were practical ones: keeping latency low, stopping several heavy models from fighting over one GPU and one microphone, and making the assistant reliable when speech recognition mishears a word.

Engineering

The problems I had to solve

Hybrid cloud / local routing

The LLM layer checks connectivity over HTTPS, uses Gemini when online, puts Gemini on a cooldown after errors, and falls back to local Llama. The UI also lets the user force either engine.

One GPU, many models

A singleton SkyResourceManager owns Whisper, Silero VAD and the microphone, with separate locks for loading, inference and audio. Vision models are also a singleton so YOLO and EasyOCR are never loaded twice.

Reliable output from small LLMs

Small models often return broken JSON. I wrote a parser that extracts the first valid JSON object, repairs common mistakes and validates every tool result against a strict schema with Pydantic.

Fixing speech errors before the LLM

A command resolver corrects mis-heard words (“clothes spotify” → “close spotify”) using regex patterns plus RapidFuzz matching. A fast router handles common commands directly, skipping the LLM.

Understanding Roman Urdu

The planning prompt maps mixed-language commands to actions, for example “Desktop se report.pdf Haris ko bhejo” → send_file(target="Haris"), and treats words like “desktop” as a file source, not a contact.

Commands by email

An email trigger polls Gmail through the Gmail API every 30 s, runs commands it receives through the same agent, and replies with the file attached, so SKY can be used remotely.

Context awareness

SKY reads the foreground window, so “pause” or “next” goes to Spotify when Spotify is in focus and to YouTube when the browser is. Recent actions are kept in an operational memory.

Full-stack product

FastAPI server with JWT login, chat sessions in SQLite, a WebSocket that streams each pipeline stage (listening, planning, acting) to a React interface, and a window manager that docks SKY beside the user's work.

In use

What happens after “Hey Sky”

  1. 1

    The microphone streams 16 kHz audio. Silero VAD and an energy gate decide when someone is speaking.

  2. 2

    Whisper checks a rolling window for “Sky” or “Hey Sky”, plays a chime, then records until 1.5 s of silence.

  3. 3

    The transcript is cleaned and corrected, then either fast-routed or sent to the LLM for a JSON plan.

  4. 4

    Tools execute each step; results are validated and the reply is spoken back in streamed chunks.

Process

How I work on it

SKY has gone through several rewrites. I treat it like a real product: I review the code, measure performance and remove what no longer earns its place.

Code review and refactoring

  • Full codebase review: removed dead modules and stale backups
  • Migrated validators from Pydantic v1 to v2
  • Replaced hard-coded paths with project-relative ones

Measured decisions

  • Benchmarked Qwen 2.5 7B against Llama 3.2 3B for latency
  • Compared five Whisper sizes for accuracy and speed
  • Quantised STT to fit an 8 GB VRAM budget

Robustness

  • Bounded timeouts on every model call so nothing hangs
  • Graceful fallbacks: GPU → CPU, cloud → local, SAPI voice
  • Detailed logging per subsystem for debugging
Future scope

Where I want to take SKY next

SKY works well for one user on one laptop. The next steps turn it into a research platform for accessible, multilingual, on-device AI.

Next · engineering
  • Fine-tuned Urdu speech modelFine-tune Whisper on Urdu and Roman Urdu code-switched speech to cut transcription errors for South Asian speakers.
  • Custom “Hey Sky” wake wordTrain a small dedicated wake-word model so detection runs on CPU in milliseconds and frees the GPU.
  • Fully local voiceReplace cloud TTS with an on-device neural voice so the whole assistant works offline.
Then · intelligence
  • Vision-language agentUse a multimodal model so SKY can understand any app's screen and plan multi-step tasks, not only click known targets.
  • Long-term memory with retrievalAdd a vector store so SKY remembers the user's files, contacts and habits and answers questions about their own documents.
  • Safety and confirmation layerRisk-score each planned action and ask for confirmation before anything irreversible, like deleting files or sending messages.
Later · impact
  • Accessibility editionA hands-free computer for people with motor or visual impairments, tested with real users.
  • Cross-platform and mobilePort the tool layer to Linux and Android so the same agent controls phone and laptop.
  • Open benchmarkPublish a dataset and benchmark of bilingual desktop voice commands to measure assistants on low-resource languages.
Research interest

The question I want to study in graduate research: how can capable AI agents run reliably on consumer hardware for speakers of low-resource and code-switched languages? SKY already gives me a working testbed for speech recognition, small-model planning and safe tool use, and I would like to develop it into rigorous, published work under expert supervision.
